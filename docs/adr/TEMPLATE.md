# ADR NNNN — Short decision title

- **Status:** Proposed
- **Date:** YYYY-MM-DD
- **Phase:** improvement_v2, Phase N (optional)
- **Supersedes:** ADR NNNN or "nothing"
- **Superseded by:** ADR NNNN (only when this record is no longer current)

## Context

What situation forced a decision? Describe the constraints, the failure mode that existed before, and any measurements that informed the choice. A reader who was not present should be able to understand why this was worth recording.

## Decision

State the decision in one or two sentences, then list the concrete parts. Use "we will" or the imperative consistently. Include the boundary of the decision: what it does **not** cover.

## Consequences

### Good

- What becomes easier, safer or faster.

### Bad

- What becomes harder, slower or more restrictive. Be honest; an ADR with no downsides is usually incomplete.

### Neutral

- Trade-offs that are neither a win nor a loss, or follow-on work that is now possible.

## Alternatives considered

For each alternative, state the option and why it was rejected. Include the "do nothing" option if it was credible.

## References

- Implementation files, tests, issues or prior ADRs.
- The relevant phase in `improvement_v2.md`, if applicable.
